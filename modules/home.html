Module 05

Home

Brainstorming

Home is the one screen we are deliberately not building yet. It exists because the ObjectiveDone CRM mobile app and the Admin Dashboard may want a daily dashboard to live here — the day's highlights, follow-ups to make, what the team has been up to — so its features stay undecided on purpose until those products take shape, rather than guessed today. Until then the screen says so honestly, and points you to the tabs where your cards, contacts and scans already live.

T

What powers this module

Feature by feature — what each moving part actually runs on.

  • The Home surface itselfNothing yet — honestly. It is a static React Native screen with a holding note and a sign-out button; no data source, no store, no cloud table behind it.
  • The chrome around itTop bar, notification bell and the tab bar with the gold Scan dock are built in React Native — the full stacks are listed under the Cards and Notifications modules' Tech stack tabs.
  • Profile circleSupabase PostgreSQL · profiles table, live since 27 July, with per-account security rules scoping every read to the signed-in member. The avatar image itself is still a device file path until the upload milestone.
  • Bell and unread badgeSupabase PostgreSQL · notifications table, live since 27 July. The count is re-read whenever a screen comes back into focus; Supabase Realtime is available but deliberately not switched on yet.
  • Sign outSupabase Auth session end + full local wipe (query cache and stores cleared), so nothing personal survives on the phone.
  • Everything elseTo be decided with the CRM phase — no stack gets chosen until the features are.

  • Decide whether everyone sees the same Homeaudience undecidedAccounts already carry a member-or-admin role, so a manager's Home could legitimately differ from a member's. Settling this before design avoids building one screen twice.
