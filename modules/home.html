Module 05

Home

In progress

Home is the day's first screen, and it is the app's follow-up surface. It opens on a greeting and the people who need you today — overdue follow-ups in red, due-today rows marked in gold — each clearing with one-tap Done or Snooze, plus any introductions waiting for your approval. Below that sit the people you met most recently, each with a one-tap Remind, and your network's own numbers. Set a follow-up in two taps and the phone buzzes when it falls due, even with the app closed; tapping the alert lands you on the person.

01

The daily landing

Built · runs on live data

Open the app and Home answers one question — who needs you today. Overdue follow-ups sit at the top in red, due-today rows carry a gold dot, and each clears with a single tap. When nothing is due, it says so honestly. And it opens honestly offline too — with no connection at all, a cold start reaches your saved cards in about three seconds with a plain "Offline — showing your saved cards" notice, instead of a long wait ending in an error.

02

Setting a follow-up

Built · runs on live data

Two taps, no date-picker wheel. Pick a preset time, add a note if you like, and forget about it — the server watches the clock, so the phone buzzes when the reminder falls due even if the app has been closed all day. Tapping the alert opens the person it is about. Typing that note no longer fights the keyboard either — any field the keys would cover now lifts itself into view, verified on the phone.

03

The app's chrome

Built · runs on live data

The frame around every screen — profile circle, mic and bell up top, the gold Scan dock below, and how the bar knows when to disappear. The mic opens the new Meeting Recorder. The name, initials and unread count behind it all come from the cloud.

A

The reminder loop

Live on the cloud

What makes a follow-up trustworthy: the phone only writes the reminder — the server watches the clock. A job sweeps every five minutes for anything due, writes the alert, and the same push pipeline that already carries every other notification delivers this one. Each reminder announces exactly once; snoozing moves the time, and it announces once more at the new time.

B

What feeds the Home screen

Live on the cloud

Home invents no counters of its own. The people and where each one came from are read off the contact list the phone already holds — the same cached copy the Contacts tab uses, so nothing loads twice — while reminders, waiting introductions and the card-view numbers come fresh from the cloud. Pull to refresh, and it refreshes itself whenever you come back to it.

T

What powers this module

Feature by feature — what each moving part actually runs on.

  • Follow-up remindersSupabase PostgreSQL · a reminders table added by migration 0011 (applied and verified), with owner-only security rules on every read, insert, update and delete.
  • The due-time sweeppg_cron · a server job runs every five minutes, finds reminders that have fallen due, writes a notification for each and marks the reminder announced, so nothing fires twice.
  • The push itselfThe chain the app already uses for every alert: pg_net calls the push-send edge function, which delivers through Firebase — which is why a due reminder buzzes the phone with the app closed.
  • The network's numbersacquisition_summary() (migration 0010) supplies card views and share-back counts; contact totals and how each contact was acquired are derived from the contact list the phone already holds.
  • The screenReact Native · TanStack Query reads the same contacts cache as the Contacts tab, so Home adds no second copy of the data; Reanimated animates the section entrances; the follow-up preset picker is a bottom sheet.
  • The chrome around itTop bar, notification bell and the tab bar with the gold Scan dock — their full stacks are listed under the Cards and Notifications modules' Tech stack tabs.
