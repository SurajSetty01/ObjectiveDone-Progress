T

What powers this module

Feature by feature — what each moving part actually runs on.

  • Scanner UIReact Native 0.80 (New Architecture) + TypeScript · react-native-svg morphing viewfinder (QR square ↔ card shape) · Reanimated transitions · mode toggle, torch, gallery and shutter controls — all built
  • CameraLIVE — react-native-camera-kit. Full-screen preview, working torch and shutter, verified on a real Android device. Chosen over vision-camera because vision-camera v5 has no Android implementation of QR scanning at all, and because it adds no native dependency that could collide with the app's storage layer
  • QR decodingLIVE on both platforms — camera-kit's built-in scanner restricted to QR, plus Google ML Kit barcode scanning for codes inside a photo from the gallery. Both paths end at the same result card, so a screenshot of a code behaves exactly like one held up to the lens
  • Card text readingLIVE — Google ML Kit text recognition, running ON THE DEVICE. The model ships inside the app, so it works in aeroplane mode, costs nothing per scan, and no photograph of anyone's card is uploaded anywhere
  • Understanding what was readTwo layers. Patterns that are unambiguous — phone, email, website, social links — are matched on the device. The judgement calls — which line is the company and which is a slogan, job title versus department, the postal address — go to an AI model (Cloudflare Workers AI) as TEXT ONLY, never the image. Every value it returns is checked against the card text before it is accepted, so it can only choose words that were actually printed; it cannot invent a company name
  • Paper-card pathShutter → on-device reading → the SAME full contact editor used when adding a contact by hand, opened pre-filled. Not a reduced copy of that form — one editor means one set of rules. The card photo uploads to cloud storage at the same time the text is being read, so nothing waits on it
  • SavingSupabase PostgreSQL contacts table — live since migration 0004 was applied and verified on 27 Jul 2026 · every row is owner-scoped by row-level security, so a scanned contact is readable only by the account that saved it (proven with two separate signed-in sessions) · the save runs as a TanStack Query mutation that refreshes the contacts list on success
  • Card photosLIVE — the captured still uploads to Cloudflare R2 and the contact stores a reference to it, so the picture follows the account to any device and survives a reinstall
  • Offline behaviourLosing the connection never fails a scan. The on-device reading still runs and still fills in phone, email, website and social links; only the AI-judged fields are skipped, and the form opens regardless
  • Form stabilityA native crash on save — a text field still holding focus while the screen was being torn down, which tripped an unguarded null inside React Native's scroll-view focus search — was found, fixed and rolled out to every form screen including Save contact; verified on a real device
P

Things to do

What is left on this module. Almost everything that was on this list has now shipped — the camera, QR decoding on both platforms, card text reading, understanding what was read, and photo uploads all came off it on 29 Jul 2026.

Quality 2 items

  • Tune the reading against real cardsReading is strong and deliberately cautious — it leaves a field blank rather than guessing, and it can never invent a value. What it still needs is a run against a stack of real Indian business cards, so the weak spots can be found on actual print rather than assumed
  • Reading a second card in the same photoToday one photo means one contact. Cards photographed two-up on a desk are a common habit and currently only the stronger one is read

Integrations 1 item

  • Verify the whole flow on iPhoneThe camera, QR and reading code is written to run on both platforms and the iPhone project is fully configured for it, but it has never been compiled on Apple hardware — that needs a Mac. Nothing is known to be wrong; it is simply unproven

Decisions 1 item

  • Reading harder cardsundecidedGlossy stock, reversed-out type and heavy design can defeat on-device reading. A paid cloud vision service would cover those, at roughly ₹0.14 a scan. Deliberately NOT built yet: the right way to decide is to scan twenty real cards and count the failures, rather than pay for a problem that may not exist
