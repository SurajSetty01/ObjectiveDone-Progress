Module 07

Scan

In progress

Tap the gold dock and the whole screen becomes a scanner — a glowing viewfinder that reads QR cards or snaps paper ones straight into your contact book. The whole path is live on Android: camera, QR decoding, card reading, and saving to your own private space in the cloud. Today the reading got noticeably better — the address no longer gets cut off — and a database rule that had been quietly refusing scanned saves was found and fixed, so both QR and card-photo contacts save cleanly. Once saved, a follow-up can be set from the contact in two taps.

A

How scanning is wired

Live end to end

Everything here is live. A scanned contact goes straight into your own private space in the cloud, the card photo uploads alongside it, and both come back on any device you sign in on. The card image itself is never sent for AI reading — only the text that was recognised on the phone. Each contact also remembers how it arrived — QR or card photo — the same numbers Home shows for your network. A database rule that had been quietly refusing saves carrying that detail was fixed on 1 Aug; both paths now save.

T

What powers this module

Feature by feature — what each moving part actually runs on.

  • Scanner UIReact Native 0.80 (New Architecture) + TypeScript · react-native-svg morphing viewfinder (QR square ↔ card shape) · Reanimated transitions · mode toggle, torch, gallery and shutter controls — all built
  • CameraLIVE — react-native-camera-kit. Full-screen preview, working torch and shutter, verified on a real Android device. Chosen over vision-camera because vision-camera v5 has no Android implementation of QR scanning at all, and because it adds no native dependency that could collide with the app's storage layer
  • QR decodingLIVE on both platforms — camera-kit's built-in scanner restricted to QR, plus Google ML Kit barcode scanning for codes inside a photo from the gallery. Both paths end at the same result card, so a screenshot of a code behaves exactly like one held up to the lens
  • Card text readingLIVE — Google ML Kit text recognition, running ON THE DEVICE. The model ships inside the app, so it works in aeroplane mode, costs nothing per scan, and no photograph of anyone's card is uploaded anywhere
  • Understanding what was readTwo layers. Patterns that are unambiguous — phone, email, website, social links — are matched on the device, and those fields stay with the pattern pass. The judgement calls — name, company, job title, department, the postal address — go to an AI model (Cloudflare Workers AI) as TEXT ONLY, never the image, and the model's answer decides those fields. Its reply used to be cut off before it reached the address; that was fixed on 1 Aug, and the reading budget was re-measured from six to twelve seconds so the answer arrives before the form gives up waiting. Every value the model returns is checked against the card text before it is accepted, so it can only choose words that were actually printed; it cannot invent a company name
  • Paper-card pathShutter → on-device reading → the SAME full contact editor used when adding a contact by hand, opened pre-filled. Not a reduced copy of that form — one editor means one set of rules. The card photo uploads to cloud storage at the same time the text is being read, so nothing waits on it
  • SavingSupabase PostgreSQL contacts table — live since migration 0004 was applied and verified on 27 Jul 2026 · every row is owner-scoped by row-level security, so a scanned contact is readable only by the account that saved it (proven with two separate signed-in sessions) · the save runs as a TanStack Query mutation that refreshes the contacts list on success · each contact records how it arrived — QR or card photo — since migration 0010 (applied and verified 1 Aug 2026); a security rule had not yet allowed those new values and was quietly refusing scan saves, which applying the migration fixed
  • Card photosLIVE — the captured still uploads to Cloudflare R2 and the contact stores a reference to it, so the picture follows the account to any device and survives a reinstall
  • Offline behaviourLosing the connection never fails a scan. The on-device reading still runs and still fills in phone, email, website and social links; only the AI-judged fields are skipped, and the form opens regardless
  • Form stabilityA native crash on save — a text field still holding focus while the screen was being torn down, which tripped an unguarded null inside React Native's scroll-view focus search — was found, fixed and rolled out to every form screen including Save contact; verified on a real device

Things to do

This module is finished on Android. The camera, QR decoding, card text reading, understanding what was read and photo uploads all shipped on 29 Jul; reading quality against real cards — including more than one card in a single photo — was signed off on 31 Jul, and the reading got a further server-side lift on 1 Aug. On iPhone the scanner now runs — camera, torch, QR decoding and card reading were all verified on a real device on 1 Aug — but the fields pulled off a paper card are not yet as good as Android's. Closing that gap is the one item left, and it does not count against the percentage above.
