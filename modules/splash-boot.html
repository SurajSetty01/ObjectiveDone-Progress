Module 01

Splash & App Boot

Done

The app's first second does real work: while the gold logo glows, the phone quietly restores your saved sign-in, confirms this is still the phone your account is signed in on, and checks the cloud to see whether your wallet holds a card yet. All of it happens behind the logo, so the splash IS the loading screen — when it fades you are already on the right screen, whether that is Welcome, the first-card studio, or Home.

T

What powers this module

Feature by feature — what each moving part actually runs on.

  • Boot gateRootNavigator screen-set switching (auth → gate → main) — the screen set is chosen declaratively by auth + wallet state, no imperative navigation
  • Session restoreSupabase Auth persisted session restored on launch · Zustand auth store drives the navigator
  • One-phone lockACTIVE since migration 0004 (applied 27 July) — the restored session is checked against profiles.current_device_id, and a phone that lost the claim is signed out at launch rather than shown stale data
  • Wallet checkTanStack Query against the LIVE Supabase cards table · zero cards keeps the first-card gate up, the first save flips it
  • Splash screenReact Native + theme tokens · the ONLY loading screen. Session restore and the wallet check both finish behind the logo, so the app opens straight onto its first real screen — a second spinner after the splash was defeating the point of having one
